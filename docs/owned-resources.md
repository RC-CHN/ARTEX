# 自有资源库

资源库位于“功能 → 自有资源库”，与任务发现的资产分开存储。资源可以只有文字说明，也可以组合文件、多个架构的工具、连接信息和配置。类型用于检索，不限制内容组合。Agent 默认获得 `resource-creator` Skill，通过显式工具维护草稿、验证并发布。

每个资源以 `RESOURCE.md` 为入口：YAML 头部包含 `name`、`description` 和可选 `tags`，正文为 Markdown。发布时从入口生成搜索元数据。文件使用相对目录，不允许路径穿越或符号链接导入。Agent 先在任务内编辑文件，再提供 SHA-256 导入草稿；不会扫描整个任务历史。

## 版本与实时更新

创建任务时可以勾选资源，名称、摘要和固定版本作为任务上下文追加到对话，正文和文件由 `use_resource` 按需读取。资源列表不放进 system prompt；恢复同一上下文时相同快照去重。发布其他版本不会重写当前会话的 system/tool 前缀。

集群内读取已选版本的只读共享挂载；外部 Runner 使用现有快照传输。启动只处理已选资源。发布先完成不可变版本目录，再提交数据库记录，失败不会暴露半份版本。

使用 Kubernetes 共享模式时，还需为 `/app/data/.resource-library/versions` 配置一个只读 `shared_mounts` 映射和对应 PVC；见 [Runner 配置](experimental-runners.md)。映射只覆盖已发布版本目录，不能映射整个控制端数据根目录。升级时先创建存储端目录与映射，再滚动更新 Runner 管理器；无需复制任务历史。

运行中的已选资源在模型回合之间检查版本索引，每次最多 32 个资源、每个运行最多每五秒检查一次。文件不参与此检查。通知追加到对话并显示在执行记录中，不中断当前工具。短暂数据库故障跳过本次通知检查，下次重试；重启后从持久版本索引补查。暂停任务不会因为资源更新自行恢复。

Agent 可以继续原版本，也可以明确调用：

```json
{"resource_id": 1, "version_id": 9, "expected_version_id": 7}
```

`use_resource` 在事务内核对当前固定版本，两个 Worker 同时切换时只有与当前状态匹配的操作成功。切换影响任务后续领取；已经返回的旧目录和正在使用旧目录的程序继续存在。当前沙盒未挂载的新版本通过任务工作副本提供，下次执行可直接只读挂载。全局发布和单个 Runner 的服务可达性观察独立，单次失败不会停用全局资源。

## 权限、凭据与持久化

全局资源可被任务使用和维护；受限资源须先绑定任务，创建该资源的任务也可维护。人类管理使用范围和停用状态，Agent 不修改这些策略。撤销绑定阻止后续领取凭据，无法收回已经读取到的文件或秘密。

凭据独立使用 AES-GCM 加密保存，工具返回任务内的凭据文件路径，不返回秘密正文。不要把秘密放入 RESOURCE.md、URL、发布说明或状态记录。备份必须同时包含 PostgreSQL、数据目录下 `.resource-library` 和原有 `jwt.key`；更换或丢失该密钥后无法解密原凭据。

升级只新增资源库和 Runner 诊断表，不转换原有资产。任务归档保存版本引用，恢复时不会自动选择最新版；资源版本缺失时给出警告。归档不复制全局资源库，因此迁移须包含上述全局备份。

## 上限与清理

- 单文件 256 MiB；每版本 2,048 个文件、1 GiB、32 个端点。
- 每任务最多选择 32 个资源，所选版本总计 1 GiB。
- 资源库逻辑总量 10 GiB、100,000 个文件条目、10,000 个发布版本。
- 编辑中草稿每资源最多 16 个、全库最多 256 个。

额度包含已发布版本和编辑中草稿，文件去重不抵消逻辑额度。超过上限明确失败，不跳过文件。每 30 分钟清理超过 24 小时且无引用的临时文件和孤立内容，不扫描任务目录，不删除已发布版本或任务工作副本。保留的旧工作副本仍受任务自身生命周期管理。

## Runner 会话失效诊断

新版 Runner 协商独立心跳通道，命令轮询延迟不会直接缩短已确认安全的租约。租约撤销、进程停止会向控制端回报固定原因码；控制端终止失效会话的模型循环，保留未知工具结果语义，禁止自动重放可能有副作用的工具。

`GET /api/runners/sessions?task_id=…&intent_id=…` 返回会话状态、节点、租约和固定错误码。相同投影与 Runner 状态原子写入 `runner_diagnostics`，运维可以查询该表，不需要展开含任务内容的 `runner_state.payload`。部署重启时仍按原逻辑将孤立 running 意图恢复为 open，并保留任务暂停状态。
