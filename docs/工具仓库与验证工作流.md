# 工具仓库与验证工作流

默认完整镜像提供常用 Python 包、网络/SSH 工具、固定版本扫描工具和 `artex-kit`。多架构制品独立于任务文件；六个原生 Skill 将发现、真实会话验证、工具分发与现有证据/复测流程衔接起来。新增功能不会自动启动协调器、配置真实凭据或向目标发送请求。

## 默认执行环境

`artex-kit inventory` 返回当前 Runner 实际可见的命令、Python 包版本与协调器是否配置。自定义镜像可能缺少部分能力，不能仅因为 Skill 存在就认定工具已安装。

- Python：Paramiko、requests、httpx、dnspython、BeautifulSoup、lxml、PyYAML、cryptography、PyCryptodome、ldap3。完整传递依赖固定在 `deploy/container-tools/requirements.lock`，构建使用 `--require-hashes --only-binary=:all:`。
- 系统命令：OpenSSH client、sshpass、rsync、socat、tcpdump、traceroute、mtr、iproute2、net-tools、strace、lsof、procps、psmisc、BusyBox static、zip、xz、zstd，以及原有 curl、wget、jq、Nmap 等。
- 专项工具：原有 Nuclei/vulnx，新增 httpx、Katana、ffuf、sqlmap、testssl、subfinder、dnsx、naabu、tlsx、yq、Chisel 和 Interactsh client。
- 协议客户端：grpcurl 1.9.4、websocat 1.14.1 默认安装在 Linux amd64/arm64 镜像，支持 gRPC（反射或 proto/protoset）与 WebSocket（ws/wss）。版本、官方制品 SHA-256 与许可证随工具目录固定；可通过 `artex-kit inventory` 查看当前环境是否可用。配套 `protocol-check` Skill 提供 schema、认证、TLS、消息边界和证据处理流程，默认可见且保留用户禁用选择。
- Playwright 浏览器继续复用；api-recon 额外需要的 Puppeteer 已固定并离线预装。其输出显式标记 `mock-runtime` 和 `backendVerified: false`。

Python 的 `import httpx` 与 ProjectDiscovery 的 `httpx` 命令共存。Python 包不需要在任务运行时联网安装。原始套接字、抓包等能力仍取决于执行环境权限；安装命令不会给 Runner 增加 root、NET_RAW 或其他 capability。

镜像构建可通过 `DEBIAN_MIRROR`、`PIP_INDEX_URL`、`NPM_REGISTRY` 和 `PLAYWRIGHT_DOWNLOAD_HOST` 选择镜像源；Python/npm/工具制品的版本与哈希不随镜像源变化。apt 包仍遵循已有基础镜像的软件源更新策略。

需要通过宿主网络代理下载工具时，先运行 `python3 deploy/prefetch-tool-artifacts.py --platform linux/amd64`。脚本将公开制品校验后放入被 Git 忽略的构建缓存，支持断点续传；Docker 构建通过只读 bind mount 取文件，缓存归档不会成为镜像层，也无需把宿主代理变量或凭据传入构建。

## 离线 IP 数据

默认镜像在 `/opt/artex-kit/ip-data` 预装 ip2region IPv4/IPv6 XDB 和 DB-IP ASN Lite MMDB，合计约 55.3 MiB。下载不需要账号或密钥，普通查询不使用网络、DNS 或第三方 API。数据库文件与 CPU 架构无关，不复制进任务目录。`ip-lookup` Skill 默认可见，保留用户编辑及禁用选择。

```sh
artex-kit ipdb status
artex-kit iplookup 8.8.8.8 2001:4860:4860::8888
artex-kit iplookup --file ips.txt > ip-attribution.json
printf '%s\n' '8.8.8.8' '::1' | artex-kit iplookup --file -
```

输入仅接受 IP 字面量，单批最多 10,000 个，每行最多 256 字符。返回 JSON，将 `geo` 和 `asn` 分开，包含来源、各库生成日期、哈希、署名链接及旧数据标记（超过 90 天）。IPv4-mapped IPv6 归一化为 IPv4；私网、回环、链路本地、组播、CGNAT 和保留地址单独分类。域名、CIDR、端口与 zone ID 不会被自动解析。

库缺失或损坏时返回 `partial` / `unavailable`，没有匹配则为 `not_found`，不静默改用在线服务。ASN 组织不能等同业务资产所有者，城市信息为估计值。结果展示应保留 [ip2region](https://github.com/lionsoul2014/ip2region) 和 [DB-IP](https://db-ip.com) 的来源署名。

更新独立于查询；管理员可在具备锁定 Python 依赖的构建环境准备候选版本，然后审核并安装：

```sh
# 联网步骤：发现公开上游版本、下载并验证原生数据库，成功后写候选清单。
python3 deploy/refresh-ip-data.py --output /tmp/ip-data.next.json

# 离线安装：所有来源通过 SHA-256、大小和实际读取检查后，原子切换 current。
artex-kit ipdb install --manifest /tmp/ip-data.next.json \
  --archives deploy/container-tools/download-cache --offline \
  --data-dir /srv/artex-ip-data

# Runner 只读挂载该目录，设置 ARTEX_IP_DATA=/srv/artex-ip-data。
artex-kit iplookup --data-dir /srv/artex-ip-data 8.8.8.8
```

构建镜像时使用仓库中的 `toolkit/ip-data.lock.json`，不自动追随最新数据。需要刷新默认镜像时，把已验证的候选清单更新为该锁文件并重建。`refresh-ip-data.py` 只生成候选清单和下载缓存，不安装到现有 Runner，也不创建定时任务；可由管理员的独立更新作业调用。更新失败保留原版本，当前批次始终读取同一快照。旧快照不会自动删除，待所有引用它的 Runner 执行结束后再回收，避免破坏运行中的读句柄。查询启动只读取小型元数据和索引，不重新扫描、哈希整库；完整校验只发生在安装时。

## 固定制品与离线分发

`toolkit/catalog.lock.json` 锁定官方制品，首批平台为 Linux amd64/arm64 和 Windows amd64。每个条目包含来源、版本、压缩格式、精确成员名称、架构、ABI 说明与 SHA-256。

```sh
artex-kit inventory
artex-kit catalog
artex-kit --cache /private/tool-cache fetch jq --platform linux/amd64
artex-kit --cache /private/tool-cache fetch jq --platform linux/amd64 --offline
artex-kit --cache /private/tool-cache stage jq --platform linux/amd64 --directory ./jq-transfer
artex-kit clean ./jq-transfer/receipt.json
```

默认镜像的本机架构缓存位于 `/opt/artex-kit/cache`，另在 `/opt/artex-kit/portable/` 内置 ffuf、yq、Chisel 的 60 个跨架构压缩包（约 249 MiB）。运行时默认目录合并这些平台，这三种工具的所有平台均使用镜像内的本地归档；按需解压到显式缓存或 HOME 下的私有缓存，支持断网使用。其他工具未内置的平台仍需要先下载。镜像内的归档和已预热缓存保持只读。启动不会扫描整个工具仓库，也不会把整库复制到任务目录。

制品下载与解包有大小限制，校验后才原子发布。ZIP/TAR 只读取精确二进制成员与小型许可证文件；拒绝重复二进制成员、链接和路径逃逸。已有文件不会被 stage 覆盖，清理只处理回执中哈希仍一致的文件。

工具库是固定版本下载与分发机制，不是远程执行服务。`transfer` 使用已有 SSH 身份通过 SFTP 上传并校验，不启动上传的二进制：

```sh
artex-kit transfer jq --platform linux/amd64 --host HOST --user USER \
  --key KEY_FILE --known-hosts KNOWN_HOSTS --base /tmp --receipt transfer.json
artex-kit remote-clean transfer.json --host HOST --user USER \
  --key KEY_FILE --known-hosts KNOWN_HOSTS
```

目标不需要 Python；它需要可用 SFTP。记录已知主机密钥，未知或变化的主机密钥不会自动接受。传输回执记录端点、远端目录、版本和校验值，不保存私钥或密码；开始上传前先保存 pending 回执。修改过的文件、有额外文件的目录不会被自动删除。Windows 的 SFTP 路径采用服务端提供的绝对路径，不能假定 Unix `/tmp` 存在。

## 嵌入式与其他架构包

```sh
python3 deploy/build-portable-tools.py --jobs 3
```

默认 Dockerfile 的独立构建阶段会执行同一脚本，把压缩包、来源与许可证放入镜像，交叉编译器和模块构建缓存不进入运行层。构建脚本要求 `toolkit/portable-build.lock.json` 中的 Go 版本，校验固定标签源码并验证 Go 模块，自动枚举该工具链支持的 Linux 架构；ARM 分成 v5/v6/v7，ARM/MIPS 使用软浮点。另构建受支持的 Windows/macOS 目标。当前 ffuf、yq、Chisel 覆盖 20 个平台组合；每种工具的支持矩阵以生成目录为准。

输出位于被 Git 忽略的 `dist/portable-tools/`：

- `archives/`：压缩后的单文件静态 Go 程序；没有目标端动态 libc 依赖，但仍受 OS、内核、CPU 指令集约束。
- `catalog.lock.json`：使用相对本地制品路径，可直接离线导入；与官方制品目录采用同一格式。
- `source.lock.json`、`licenses/`：来源、源码哈希和上游许可。
- `build-report.json`：每个工具/平台的大小、哈希、构建及实际执行测试状态。

```sh
artex-kit fetch yq --platform linux/mipsle --offline
# 仓库外独立构建产物也可通过 --catalog dist/portable-tools/catalog.lock.json 使用
python3 ci/portable-tools-smoke.py --qemu-directory /path/to/qemu/usr/bin
```

Linux 包通过原生或显式 QEMU 用户态执行检查；32 位 x86 需允许兼容系统调用的宿主机。Windows/macOS 编译成功不等于已在对应 OS 上运行，报告明确分开。QEMU 不覆盖真实设备的老内核、内存上限或特殊固件环境。脚本不注册系统 binfmt、不上传制品，不更改集群。

## 共享验证协调器

协调器是一个显式启动、按项目隔离的常驻服务，与一次性 Runner 分开。复制 `toolkit/coordinator.example.json` 到私有目录，填写随机至少 32 字符服务令牌、允许的 origin、预算和测试身份；配置文件权限必须是 0600。创建 0700 状态目录：

```sh
artex-kit serve --config /private/coordinator.json --state /private/verification-state
```

默认只监听 `127.0.0.1:8790`。跨 Runner 使用时配置 TLS 反向代理和访问范围，在 Runner 提供 `ARTEX_KIT_URL` 与只读 `ARTEX_KIT_TOKEN_FILE`；客户端拒绝非回环明文 HTTP 和携带认证的重定向。服务令牌是项目级能力，同一令牌的客户端可以读取该项目的验证记录，不能跨不互信项目共用。

SQLite 状态由单进程独占，部署在支持本地锁语义的持久化卷上，不放进 NFS 工具共享目录。重启保留预算、覆盖记录、证据摘要和回调；未完成执行标记为 `inconclusive`，不自动重放可能有副作用的请求。

`origins` 的预算涵盖经过协调器的所有请求，包括会话检查、刷新与业务步骤。限制请求数、速率和并发，429/503 触发退避；窗口与累计数持久化。直接调用第三方扫描 CLI 不经过此协调器，须使用各自限速选项，不能将此机制描述为整个 Runner 的透明网络限速器。

身份使用独立 Cookie jar 和固定 origin 范围，计划通过名字引用。每次工作流先检查真实身份；可配置一次刷新及再次确认。`refresh.capture_headers` 将 JSON pointer 对应值写到指定请求头。凭据仅在协调器私有配置/内存中使用，结果包含脱敏响应摘要，完整认证头不进入结果。

## 工作流、覆盖与回调

加载原生 `authenticated-verify` Skill 获取完整计划示例。调用：

```sh
artex-kit verify plan.json --output verification.json
artex-kit status RUN_ID
artex-kit callback RUN_ID --ttl 3600
```

计划具有 `test`、`revision`、1–30 个 `steps`，至少包含一个明确的响应断言；缺少断言或使用未知断言字段会在执行前拒绝。每步指定身份、证据角色、HTTP 请求、响应语义断言及可选字段提取。`capture` 使用 JSON pointer；后续 URL 可用 `{{name|url}}` 安全编码。请求/响应各限制 1 MiB，响应摘要限制 4096 字符。JSON pointer 比较保留业务语义，避免仅用状态码或长度判断权限问题。

相同计划和身份/范围配置默认复用记录，重复客户端请求不会再次执行。明确复测时使用新的 revision 或 `repeat: true`；重试前检查已完成的有状态步骤。默认最多保留 10000 条运行记录，达到上限后拒绝新执行，须先导出并轮换状态目录，不能静默删除仍被引用的证据。

状态 `observed`/`not_observed` 表示断言是否观察到，`inconclusive` 表示条件不足。它们不自动创建漏洞，也不自动将已有漏洞判为修复。现有 ARTEX 流量证据和复测接口继续由 Skill 调用；协调器哈希与文件证据不冒充数据库里的流量 ID。

HTTP 回调使用随机能力 URL，关联已存在的运行记录；有效期最多 24 小时，每个回调最多保留 32 条摘要事件，支持 Runner 退出后的迟到事件。配置 `callback_base` 才返回可访问 URL。此服务只提供 HTTP 回调；DNS/SMTP 等协议使用另外配置的 Interactsh 服务。回调到达不是自动漏洞结论，仍需与请求和对照关联。

## 验证与回归

```sh
PYTHONPATH=toolkit python3 -m unittest discover -s toolkit/tests -v
go test ./toolenv ./skills ./runner ./runnernode
```

SFTP 集成测试需要锁定的 Paramiko 依赖；测试只启动本地合成 HTTP/SSH 服务。镜像冒烟测试另外验证非 root、只读根文件系统、真实 CLI、Python 库和离线浏览器，见 `ci/toolkit-image-smoke.py`。六个新 Skill 与原有 Skill 一样：缺失文件才播种，用户修改和已禁用的可见性选择保持不变。
