# Worker 预算、撤除登记与记录导出

## Worker 的 150＋10

默认每个 Worker 意图可执行 150 轮，之后追加明确的预算通知并进入最多 10 轮收尾：保存事实、证据路径、部署登记和未完成事项，最后以纯文本汇报。最后一轮会再次提示直接汇报；用完后保留已有记录并结束执行。收尾阶段 Bash 在执行层禁用，包括通过 ExecuteExtraTool 间接调用；记录、读取和汇报工具仍可用。

预算按意图持久累计，模型迭代前事务预留；并发预留不会突破上限，进程中断不退还可能已经执行的轮次。暂停、重试、上下文压缩和服务重启不重置额度。输出恢复迭代计入轮数，底层网络重试和压缩模型调用不单独计轮。这是执行轮数限制，不是费用或累计 token 硬上限。

新安装使用 150＋10；升级时一次性把旧 Worker 的 0 默认迁移为 150＋10，已有正数自定义值保留。迁移之后再明确设置 0 表示不限常规轮数。旧意图从升级后首次执行建立账本，不追溯历史轮数。修改默认配置只影响尚未建立账本的意图。

Worker 用 `get_worker_budget` 查自己的预算，需要追加时调用 `ask_main_agent` 说明进度、证据和具体所需轮数。主 Agent 用 `grant_worker_budget` 提交原意图 ID、刚读到的 revision、追加值、理由和稳定 request_id；人类可在任务“记录与收尾”操作。相同参数重试不重复追加，过期版本返回冲突及重新读取提示。Worker 自己调用会被拒绝。追加不自动重跑或解除暂停，已停止的 Worker 从原会话继续；已经进入收尾的当前执行仍完成收尾，下次执行使用新额度。Planner 不应以重复意图绕过预算。

## 独立资源与任务部署

`resource-creator` 默认 Skill 要求按可独立使用、更新和撤除的单位登记资源。同一工具的说明和多架构文件可组成一个资源；不同位置的临时进程、代理、文件等分别登记在任务部署清单，不消耗任务的资源选择额度。

- `manage_deployments`：list/get/save，save 可批量传入 items；记录位置、准确标识、撤除方法、状态与验证。更新需要 expected_revision；保存和批量每项需要稳定 request_id。
- `resource_references`：查询资源的任务引用及部署。
- `delete_resource`：删除资源登记，阻止新使用，保留历史版本和证据。其他活动任务引用、尚未撤除的部署会阻止删除；Agent 当前任务自己的固定版本不阻止删除。
- `manage_resources_batch`：最多 25 个独立操作，逐项提交，成功项不回滚；回执列出 succeeded/failed 和逐项结果。
- `check_task_handoff`：列出待撤除、明确保留、运行或未完成 Worker、待处理主 Agent 问答。检查只覆盖已登记信息，不证明所有外部部署都已发现。

改登记和删除资源都不会执行远端命令。标为 removed 或 retained 必须提供实际验证或保留依据；结果未知不能标为成功。删除资源是保留历史的逻辑删除，不会释放已发布版本占用的配额。部署账本在任务冷归档后仍保留，避免未撤除部署失去引用保护。

## 完整记录资料包

任务“记录与收尾”可异步生成、查看进度、取消、重试和下载；任务列表可精确选择最多 20 个任务。Agent 的 `export_task_records` 只允许当前任务，不会自动扩大到关联任务或全局流量。它仅生成副本，不负责撰写渗透测试报告。

包内包括实际留存的任务与探索记录、会话和工具输入输出、模型记录与用量、任务文件、选中或任务创建的资源版本、部署与预算历史，以及绑定发现的 HTTP 证据。提供 JSONL、会话 Markdown、离线 HTML 和 manifest.json；后者记录每个文件的大小、SHA-256、快照时间及缺失原因。下载显示整包 SHA-256，支持 HTTP Range 续传。

数据库使用同一个只读可重复读快照。运行中的任务不会暂停；文件复制仅针对快照时可用内容，跳过符号链接、特殊文件和检测到的并发变更，并记入缺失清单。它不是冻结整个文件系统的原子快照：文件与数据库可能存在时间差，包内明确说明。

未录制的模型请求、已经清理的文件不能恢复。全局历史代理流量没有可靠任务归属，因此只导出已明确绑定的流量证据，不按域名猜测并混入其他任务。部署只关联资源 ID、没有固定版本时，资料包保留资源描述与部署登记，不猜测其实际部署版本。凭据库密文不导出；原始任务记录和文件仍可能含秘密。

可另生成“过滤常见凭据字段”副本：结构化 JSON（含嵌套 JSON 字符串）保持有效格式，常见凭据字段和认证头被替换，二进制和超过 8 MiB 的文本附件排除并记录原因。该过滤不保证识别任意格式秘密，外发前需审阅；原始记录不修改。

生成任务持久排队，租约与每次执行的唯一 owner 防止旧进程提交结果。取消最多等待当前 I/O 或下一次心跳检查（5 秒）；进程重启后过期租约可重新生成。默认最多 10 个排队/生成任务、单包 20 GiB/20 万文件、已完成包合计 100 GiB、保留 7 天。重试也受队列限制；取消和删除导出副本都不改变原始任务。临时孤立文件按所有权和保留时间回收。

离线 HTML 按最多 200 条或约 2 MiB 拆成静态 JS 分片，页面每次显示最多 200 条。搜索按顺序扫描所有分片，快速更换查询时丢弃旧搜索结果；无需 HTTP 服务或外网。必须完整解压 ZIP，不能只复制 HTML。JSONL 和 Markdown 仍完整保留。打包直接读取已生成清单，避免再次扫描暂存目录。

可选环境变量 `ARTEX_RECORD_EXPORT_SCRATCH` 指定有足够容量的绝对路径，在其 `artex-record-export` 子目录暂存；未设置时保留原共享目录行为。完成 ZIP 始终保存到原数据目录，20 GiB 上限和租约回收规则不变。启用前应给暂存存储配置容量和节点磁盘预算。

资源发布先在共享 GC 锁下准备完整目录，再进入原配额、任务、资源、草稿锁顺序做权限与版本复核并提交。准备过程中不同资源可继续修改；GC 跳过正在准备的目录。冲突、重放和历史保留语义不变。

## 工具回执与查询完整性

工具等待并发名额时支持取消。已发布的取消回执不被迟到结果改写；`execution_status=not_started` 表示未开始，`unknown` 表示已经准入但取消时无法确认实际副作用，须先核对状态再重试。普通调用次数统计通过有界队列批量写入，队列满或数据库失败有独立计数，健康接口的 `tool_usage_queue` 只包含计数。执行结果和预算预留不走这个可丢弃队列。

`list_findings {}` 保留原数组格式；`paged=true` 可选启用 `limit/before/q` 与 `findings/total/has_more/next_before` 回执。旧数组达到可能截断的长度时附加分页提示。查询失败明确报错，态势概览的部分查询失败标记 `incomplete/query_errors`。运行中意图先按状态查询再限量，真实数量与截断标记分开返回。图活跃性分析只读取结构字段，生成摘要时才读取完整正文，发布摘要前仍重新校验活跃状态。

## 验证

本次新增测试使用临时 PostgreSQL 和合成任务，不需要读取生产任务内容。覆盖实际 150＋10 轮、并发预留、追加权限/CAS/重放、资源删除阻塞与历史保留、部署并发写入、多个任务的同一数据库快照、导出校验/续传/跨任务隔离/路径边界/凭据过滤，以及真实浏览器里的登记、验证撤除、追加预算、下载与删除资源流程。`ci/lifecycle-ui-smoke.cjs` 作为发布镜像检查运行。

### 可选任务软预算与可核验交接

任务的「记录与收尾」页可设置累计输入＋输出 Token 软预算，0 为默认不限。
用量沿用 `llm_usage`，含各 Agent 和压缩调用；缓存读取不会再额外加一遍。
达到阈值后停止自动 Planner 唤醒和 Worker 领取；已运行 Worker 在轮次边界
使用原有收尾额度。并发在途请求、收尾、人工对话和主 Agent 协调仍可产生用量，
所以它不是账单上限。供应商未返回或未成功落库的用量不能凭空恢复。
修改使用 revision 比较更新，冲突须刷新；修改上限不清空历史，不自动重启
已耗尽的 Worker。暂停和归档恢复保留预算。`get_worker_budget` 与
`check_task_handoff` 均附带任务预算。

`check_task_handoff` 额外提供本任务事实、漏洞、意图的总数及最多20个最近节点 ID，
通过 `node_detail(id)`、`get_worker_trace` 和分页查询核对。
每份导出含 `tasks/<id>/handoff.json`，来源是包内同一数据库快照，提供来源文件、
状态、计数和有截断标记的最近 ID；完整 JSONL 仍保留。它不证明外部部署已撤除。

### 主 Agent 自然结束与 Worker 空回复补答

主 Agent 恢复 0.14 之前的自然结束行为：没有文字答复也没有工具调用时，
不注入补答或继续工作提示，不进入仅文字模式，也不触发 `empty_response` 保护终止。
运行循环不会强制补答或续跑。已有工具结果、产物和会话保留，后续对话仍可正常使用工具。
`completed` 只表示本轮模型自然结束，不证明用户任务已经完成；缺少文字时仍展示系统回执，
保留终态和模型输出计数等诊断信息。OpenAI、Anthropic 兼容接口的空输出和协议不完整由下面的协议层
机制处理，不进入主 Agent 补答或收尾流程。

主 Agent 默认轮数不限，不继承 Worker 的 150＋10；显式设置的 `max_turns`
及对应收尾、取消和真实执行故障仍然生效。自动 Worker 请示保留原有最多 24 轮常规执行
及后续收尾、10 分钟总处理边界和投递后的结束逻辑。主 Agent 恢复旧会话时，仍仅从工作上下文
排除紧随空 assistant 回复的旧版固定补答禁令，原始记录保留。

Worker 保留仅文字补答：工具 schema 隐藏，执行层也拒绝所有工具；不会重放
上一条命令。Worker 已进入预算收尾时也保持这一限制。补答消耗现有轮数与
Token 额度，不突破硬取消。恢复提醒只进入当次模型请求，不写入会话或压缩历史。
再次没有文字时明确标记缺少总结，系统回执不能当作任务完成证明。

### 不完整的模型响应

OpenAI、Anthropic 兼容接口分别检查传输结束和有效输出：没有结束标记的 EOF、损坏的协议帧、
残缺工具参数，以及结束后只有推理而没有正文或工具调用，均不能算正常完成。
明确的 `finish_reason` 后直接 EOF 仍兼容；存在有效正文或完整工具调用时，只有 `[DONE]`
而没有 `finish_reason` 也仍兼容。Anthropic 对应 `message_stop` 与非空 `stop_reason`，
收到任一终态依据时接受传输结束，但仍检查是否有有效输出。`max_tokens` 继续使用已有处理方式。

只有尚未输出正文或任何工具片段的空回复、缺少结束标记或读流失败，才可复用
模型配置的 `retry_empty_attempts`（SDK `EmptyResponseRetries`）预算重试当前请求，
默认额外 2 次。请求内容和工具权限保持不变，
不注入继续工作、总结或禁止工具的提示。损坏帧、无效工具参数，以及已有正文或工具片段的
不完整响应直接报错；取消始终优先。重试用尽或重试建连失败后，以 `incomplete_response`
结束，不触发模型池的额外重试或整个 Worker 意图重跑。

失败尝试的推理与签名仍可用于当前运行诊断，但不会拼接进下一次成功响应或后续请求历史。
明确上游错误保留仅供程序分类的原始原因，公开错误使用固定类别；若确认额度耗尽，仍更新
下次调用的模型选择，但不重放当前不完整响应。

此前已执行的工具结果和产物保留，未完成的工具调用不会提交执行。部分正文、未提交工具的
诊断和各次请求用量保留，界面明确显示异常终态。常开 `llm_usage` 记录会话 ID 与协议元数据，
对话活动保留固定失败类别，无需录制请求或回答正文；旧记录中未采集的协议字段保持未知，
不能据此倒推出历史响应是否收到 `[DONE]`。

活动 result 的 metadata 保存终态、轮数、耗时、是否缺少总结、恢复总次数与最近恢复模式；
`llm_usage` 保存终止原因白名单、文字/思考字节数和开始生成的工具块数，
以及 OpenAI Chat／Anthropic 流是否出现结束原因、以 DONE/EOF/错误等何种方式结束、解析错误次数，
不保存正文。未观测的协议与老记录的新字段为空，不能据此认定缺少结束标记或零输出。
工具块计数不是执行成功计数。
工具旧纯文本错误会补充 code、next_action 和保守的执行状态，已有结构化回执
及成功结果保持原样。写操作错误不等于没有生效，先核对再重试。

健康接口的 `performance` 为进程内固定阶段计数、错误数、总/最大毫秒数及
8档互斥耗时桶（≤1ms、≤10ms、≤100ms、≤1s、≤10s、≤60s、≤600s、>600s）。
阶段固定，无任务、工具名称或内容标签；重启后清零，不作为持久计费或执行回执。
