# Nuclei 定向验证

1. 先看当前执行环境的可用工具说明；必要时运行 `command -v nuclei`、`nuclei -version` 和 `nuclei -h`。外部 Runner 使用自定义镜像时可能缺少工具，应报告缺失并选择具备能力的 Runner，不要自行全局安装或升级。
2. 从任务范围、资产与 vulnx 查询结果确定目标和候选 CVE。产品名称或版本匹配只代表线索，不代表漏洞存在。优先挑选明确相关的模板，先列出并查看模板，再执行检测。

```sh
nuclei -tl -tags cve
nuclei -td -id CVE-YYYY-NNNN
```

3. 将下面占位符替换成已确认的目标和模板 ID；默认从低并发、低速率开始，按任务约束调整。每次调用使用独立的结果目录，避免多个线程覆盖同一文件。

```sh
run_dir=$(mktemp -d "$PWD/nuclei-results.XXXXXX")
nuclei -u 'https://target.example' -id CVE-YYYY-NNNN \
  -rl 5 -c 2 -timeout 10 -retries 1 -jsonl -o "$run_dir/findings.jsonl"
```

默认镜像固定了模板版本，关闭自动更新检查，可离线列出模板。最新 CVE 可能尚无内置模板；先查情报与模板来源，必要时将核对过的模板放进当前工作目录并通过 `-t` 指定，不修改共享模板目录。模板如果需要凭据、外连回调、浏览器或额外协议能力，先检查相应资源和任务约束，不把“不具备运行条件”当作“目标没有漏洞”。

网络默认直连。如果额外环境提示词声明了可用代理且本次确实需要，读取 `nuclei -h` 中当前版本的代理参数，按本次命令显式传入；不要默认设置全局代理，也不要把内网代理地址写进 Skill。

长任务可使用 Bash 后台执行，并通过 TaskOutput/TaskList 查看进度；结束或取消时确认任务状态。不要因文件上传或回执异常重复发起已执行的扫描，先核对日志与输出。

记录目标、模板 ID、工具/模板版本、执行状态和结果文件位置。命中需结合实际响应及应用行为复核；没有命中不证明无漏洞，超时、鉴权不足、连接失败需单独列明。只读已发布共享目录可用于查看其他线程结果；自身结果写入当前任务允许的目录，稳定后再共享。
